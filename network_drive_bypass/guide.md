# 突破网络驱动器备份限制指南（微信/WPS等）

## 背景
微信PC端、WPS等软件出于数据稳定性和防丢考量，通常会限制用户将“聊天记录备份”或“同步文件夹”直接放置在SMB等网络映射驱动器（如 Z: 盘）或可移动磁盘上，强制要求选择本地物理硬盘。

本指南总结了两种最主流的方法来绕过这一限制，将数据存入 NAS 等网络驱动器中。

---

## 方法一：使用 VHD/VHDX 虚拟硬盘（🌟 强烈推荐）

### 原理
在网络共享目录中创建一个大容量的 `.vhdx` 虚拟磁盘文件，并让 Windows 系统将其挂载为一块真实的本地物理硬盘。因为在操作系统底层它被识别为原生本地设备（Block Device），所以所有的软件都会对其“绿灯放行”。

### 优点
- **完美兼容**：100% 骗过所有检测驱动器类型的软件。
- **稳定性高**：原生挂载为 NTFS 格式，针对 SQLite 等数据库（微信所用）读写的稳定性远胜于纯网络文件夹共享机制。

### 缺点与风险提示
- **单点独占**：VHDX 文件在挂载使用时是被当前 Windows 系统独占锁定的。
- **跨平台读取极高风险**：如果在 Windows 挂载并使用期间，强行在 Linux（NAS服务端）使用 `qemu-nbd` 等工具尝试挂载和读取，**极易导致内部 NTFS 文件系统崩溃，数据全部丢失！**
- **建议**：除非 Windows 端已彻底脱机（断开）该 VHDX 盘，否则绝对不要在服务端 Linux 尝试读取它。

### 自动化创建脚本 (使用 Diskpart)
你可以在本目录下找到 `create_vdisk.txt`，并在“以管理员身份运行”的命令提示符或 PowerShell 中执行 `diskpart /s create_vdisk.txt` 来自动创建并挂载一个 200GB 的动态扩展虚拟硬盘（初始占用小，用多少占多少）。

```text
create vdisk file="\\192.168.2.200\data4t\VirtualData.vhdx" maximum=204800 type=expandable
select vdisk file="\\192.168.2.200\data4t\VirtualData.vhdx"
attach vdisk
convert gpt
create partition primary
format fs=ntfs quick label="VirtualData"
assign
```
*(注：建议直接使用 UNC 路径 `\\IP\路径` 避免管理员权限下识别不到映射盘符的问题)*

### 开机/重启后重新挂载
系统重启后，虚拟硬盘不会自动挂载。本目录下提供了一个 `mount_vdisk.bat` 一键挂载脚本：

- **手动挂载**：每次需要时，双击运行 `mount_vdisk.bat`，并在弹出的 UAC 窗口中点击“是”即可自动挂载。
- **全自动无感挂载**：
  1. 打开 Windows **“任务计划程序”**，点击右侧的 **“创建任务”**。
  2. 在 **常规** 选项卡中，填写名称，并**必须勾选“使用最高权限运行”**。
  3. 在 **触发器** 选项卡中，新建触发器，选择 **“登录时”**。
  4. 在 **操作** 选项卡中，新建操作，选择“启动程序”，并浏览选中本目录下的 `mount_vdisk.bat`。
  5. 保存后，每次开机进入桌面，系统会在后台静默全自动挂载该虚拟硬盘。

## 方法二：使用 `mklink` 目录软链接

### 原理
使用 Windows 原生的符号链接功能（类似加强版的底层快捷方式），将一个看似在本地的路径，静默重定向到网络驱动器的目标路径。

### 操作指令
必须以**管理员身份**运行 CMD，执行以下命令（注意：作为跳板的本地路径如 `C:\WeChatBackup` 在执行前不能已存在）：
```cmd
mklink /D "C:\WeChatBackup" "Z:\WeChatBackup"
```
完成后，直接在微信/WPS中将路径选择为 `C:\WeChatBackup` 即可。

### 优点
- **文件独立可见**：所有的备份记录、文档依然以独立文件的形式存在于网络驱动器上，不会被打包。
- **Linux (NAS) 友好**：NAS 服务端的 Linux 系统可以直接浏览、查看甚至编辑这些文件，无需繁琐的解包和挂载过程。

### 缺点
- 依赖于网络极高的稳定性。如果网络瞬间抖动或断开，正在通过软链接写入的微信数据库极其容易发生损坏。

---

## 总结与决策建议

| 需求侧重点 | 推荐方法 | 理由 |
| :--- | :--- | :--- |
| **极致稳定、无缝兼容** | **方法一 (VHDX)** | 软件识别度最好，能避免直接暴露在SMB协议下的数据库锁定问题。 |
| **需要在NAS服务端直接看文件** | **方法二 (mklink)** | 保持原生文件结构。代价是网络绝对不能断，否则极易丢数据。 |
